# Gemini 3.6 Flash 金丝雀报告（2026-07-21）

**问题**：AGY 已上架 gemini-3.6-flash。用 7/18–7/19 真实成品里"人工/权威纠正过的点"重听，3.6 的裸输出是否已经不需要这些纠正？

**结论：不需要纠正的点 = 0/13。** 3.6 听得更全（两处 3.5 整句漏听被找回）、更快（wall 时间 ≈ 3.5 的 55%），但**所有实体/专名类纠正点仍然全错**，只是错出了新表面；且出现一类新风险：**流畅化改写**（把没听清的口语改写成通顺但不忠实的句子），比明显乱码更难被门抓住。词表、裁定、回声防御一条都不能拆；回声探针里 3.6 还有一处实体表面被诱导带偏（3.5 对照未被带偏）。

## 实验设置

- 金标准：`lidousha/2026-07-18`、`2026-07-19` 六个成品 clip 的 chat-authority 记录中 29 处 before≠after，其中 13 处实质误听设硬判据（其余 16 处为弹幕原文精确化——顿号/分行/引号来自复制弹幕源文本，音频不可知，**任何模型下都永远需要纠正机制**，不计入模型分）。
- 音频：free 主机未烧字、无片头的 recut 母带抽纯音频（audio-only mp4，无视频流——成品 mp4 烧了纠正后字幕，投给多模态模型会泄漏答案）。时间轴与授权记录 final_relative 逐毫秒对齐已验证。
- 条件：生产同款杂谈精听提示词（transcribe_live_talk 版），唯一变量 `--model`：`gemini-3.5-flash-high`（对照）vs `gemini-3.6-flash-high`。AGY 订阅内共 18 作业（12 主 + 6 探针）。
- 对照有效性：3.5 对照复现了生产基线的误听族（宝宝→爸爸、李豆沙→刘沙、kmx→KiMoso、漏"舞台上"整句），说明实验听力条件≈生产。

## 行为差异（部署相关）

1. **漏听找回（↑）**：3.6 对 3.5 完全丢掉的高情绪快语速段有明显更高召回（两例）。对精听 lane 的"漏整句"类问题是真收益。
2. **实体先验依旧为零（=）**：kmx/李豆沙/侄女/贯口等圈层专名 100% 仍错。且**错误表面跨会话不稳定**：3.6 主批把 kmx 听成"猞猁熊/起莫首"，探针另一会话听成"甜熊"。词表 alias 打法不变，但若切 3.6 需按新表面补种（见下）。
3. **流畅化改写（↓ 新风险类）**：3.6 倾向把听不清的口语改写成通顺句（袅袅了→都红了、有点亏→的话、第一人称→"小理"三人称），并大量加引号/省略号。对以"口语忠实"为核心价值的字幕链路，这类错误**比乱码更难被 exact_read/support 分抓住**，需观察 danmu-first 通道的 support 分布是否漂移。
4. **cue 粒度变粗（↓）**：同素材 3.6 平均 22-24 cue vs 3.5 的 37-38。时间锚由 BCUT 兜底不受影响，但 chat-authority 的 cue 级匹配窗口会变宽，命中精度可能下降。
5. **速度/效率（↑）**：wall 中位 ≈ 3.5 的 55%（29s vs 52s/作业），与官方"输出 token 省 17%"方向一致；AGY/免费 key 同配额可多干活。

## 建议

1. **不切也不亏，切则分阶段**：3.6 的收益（漏听召回、速度、token 效率）真实但不解决主要矛盾（专名/实体全靠词表+裁定，这部分模型无关）。若切：先只切**杂谈精听 lane**（`JINGTING_GEMINI_MODEL=gemini-3.6-flash` + AGY 模型串），歌切链路（agy_lrc_alignment/onset 敏感）**本轮零证据，未做对齐 canary 前不动**。
2. **切换前置动作**：词表补种 3.6 新错误表面 alias（猞猁熊、起莫首、甜熊、小理、理拉拔、栗直/栗零、直女、罐头、林木）；观察一场影子对比（auto_review shadow）确认 danmu-first support 分布与 filler/regression 门无漂移。
3. **与模型无关的顺手发现（需修）**：free 上 agy（Antigravity CLI）当前版本 headless 自动拒绝 `write_to_file`（settings.json 无 permissions 规则），`transcribe_live_talk_via_agy.sh`/`transcribe_live_song_via_agy.sh` 会静默产出空文件且 rc=0。金丝雀用 `--sandbox --dangerously-skip-permissions` 绕过（作业目录被 add-dir 圈死）；生产脚本需择一修复（加标志或配 allow 规则）并加"空产物即失败"门。
4. 弹幕原文精确化类（16/29）与模型无关，永远走 danmu-first 通道，不进模型评价。

## 追加实验：词表预热 2×2（同日）

Ivan 问：预先给模型专名示例会怎样？加跑 12 作业：同任务提示词前注入 repo 权威 `lidousha/lidousha_glossary.txt`（逐字）+ 一句反乱种铁律（"表只规定怎么写，不暗示说了什么；音频没出现的词严禁写入"）。注：生产精听 lane（gemini_slice_jingting）本就注入该词表，当初的成品即"3.5+词表"链路仍错出来的。

**13 实质点金牌数：3.5裸=1 → 3.6裸=2 → 3.5词表=4 → 3.6词表=4。**

- **词表增益 > 换模型增益**。词表可覆盖的实体点（kmx/李豆沙/侄女/线下/舞台句）两代模型基本都救回：旗舰 kmx/李豆沙 双双 GOLD；侄女 3.6词表 GOLD（词表明写"不要改成直女"，3.6 服从）。
- **乱种（决定性差异）**：4 个旗标全在 3.5词表，3.6词表零旗标。
  - 3.5词表把音频"谢谢快乐猫猫和忧郁小狗的SC"改写成"我那 **lycoris 和 shadowlee** 的私聊里面"——真实 SC 送礼人名被词表角色顶替（发布级事故类）；

## 考古附注：词表一直都在生产链路里，为什么还需要纠正

Ivan 问"为什么之前没给 Gemini 加词表"。核实：词表**一直在**——直连 API 纠错 pass（gemini_correct）、AGY 纠错 pass（agy_prompt:998，另叠弹幕逐字+topic-entity graph）、全场转写（full_session_transcription:140）三处都注入 `lidousha_glossary.txt`，且"小寺/小室"事故后加固过防静默空词表；7/18-19 成品 `subtitle_source=aggregate_asr+bcut_agy_cpa+...` 证明就是带词表的 3.5 链路产物。本报告第一轮金丝雀不带词表是**实验设计**（裸听力单变量 A/B，用的外围 bootstrap 转写提示词），非生产条件。

带词表仍需纠正的结构性原因：
1. **3.5 对词表服从不可靠**（本报告 2×2 实测：4/13 金 + 实名顶替乱种 + 照样直女）——这正是 term_authority 后处理、danmu-first、人工裁定这些硬通道存在的理由；
2. **纠错 pass 被草稿锚定**：生产是"BCUT 草稿+音频+只改听错的"，模型不确信时保守不改（防过改的特性），错误存活到下游；
3. **词表覆盖有边界**：贯口/李0民/生日快乐类不在表内，表也不宜膨胀（稀释+扩大乱种面）；
4. **歌 lane 故意不喂**（回声防御，7/13 顺从性实锤后确立）——喂词是按 lane 划分的安全决策。

元结论：3.6 的核心红利不是听力，是**把词表从双刃剑变成单刃**（服从写法约束且不乱种）。
