## е2 决策卡片（1 张）

**原裁定**：`src/autoslice/full_session_transcription.py:364-370`（`_cpa_correct_draft_cues` docstring，Ivan 2026-07-04）——「The correction is a TEXT task, so it belongs to CPA — the same judge the rest of the pipeline uses — not agy.」文本校正决策权属 CPA judge；声学证人（AGY/agy provider）的角色标注为 `"witness_authority": "EVIDENCE_ONLY"`（见本候选每一条 `context_audio_adjudication`/`self_heal` 记录），即证人只提供听觉证据，不直接拥有裁决权。

**本案反例**：本候选中，`WITNESS_JUDGE_APPLY_PROPOSED` / `CPA_JUDGE_APPLY_PROPOSED_OVER_WITNESS_CONFLICT` 机制在 cue1、cue34、cue90、cue92（×2 跳）**四处成功修复**了草稿的真实错误（「我们你是好人吗」→「我问你是好人吗」等），但在 cue2、cue14（×2 跳）、cue53、cue97 **六处把草稿本来正确或接近正确的文本改错**——同一套机制、同一候选内，功过并存。核心机制缺口：当前架构里，最初的整句 BCUT 草稿（`asr_draft.srt`/`padded.fresh.srt` 里的 CURRENT 文本）在被重新送去窄窗口「二次听审」时，**不作为一个带自身可信度的独立证人**参与判断——它只是待替换的 `CURRENT` 候选，judge 只比较「新证人的证词 vs 旧文本」，不比较「旧证人（完整语流下的原始识别）vs 新证人（孤立短窗复听）」两个证人谁更可信。cue2 的证人证词甚至是从证人自己的听写「坏闭集重建」出来的候选，构成自证循环。

**冲突本质**：「CPA 判文本、AGY 只当耳朵」这条 2026-07-04 决策本身没有错，但它没有规定「多个耳朵意见冲突时如何加权」——本候选证明，在孤立窄窗复听与完整语流原始识别冲突时，现状机制系统性偏向相信最近一次、语境窗口更窄的复听，而这次复听在本候选里错得比原始识别更多（6 次改错 vs 4 次修对，净负）。是否收窄「窄窗证人可以推翻完整语流草稿」的条件、是否需要给原始草稿一个可比较的置信度/证人地位，是需要 Ivan 权衡的产品判断（收紧可能连带压低 cue1/34/90/92 这类真实修复的召回率），不是机械上可以单方面收窄的纯 bug。

**建议选项**：
1. 维持现状（接受净损耗，等 SOTA 分段/更高精度 witness 模型自然改善）；
2. 给原始整句草稿一个「先验证人」身份，窄窗证人与其冲突时提高应用 PROPOSED 的门槛（而非现状的「judge 选 PROPOSED 即应用」）；
3. 分歧时（`witness_conflict=true` 或两个证人文本不一致）引入第三方裁决（重新完整语流复听，而非窄窗）。
