结论

推荐把现有“两阶段”拆成四个逻辑阶段：

候选提出：现有全场 ASR → LLM 圈候选，只评其余六维；lidousha_centrality = null。

候选级说话人预检：只对仍可能入选的候选音频，运行轻量的“李豆沙 vs 非李豆沙 vs 存疑”检测。

完整打分与选择：把粗说话人标签对齐到现有 ASR，再让 LLM 按新 rubric 评 centrality，随后确定性模块算最终分。

produce：只有胜出候选进入重转写和完整分离；并且完整分离必须排在封面、烧录、打包之前，作为最后验证门。

也就是：

全场粗 ASR
  → 候选提出（六维，centrality 未观测）
  → 候选级目标说话人预检
  → centrality 评分
  → 最终选择
  → 重转写 + 完整分离
  → 封面 / 烧录 / 打包

不要选：

全场提前完整分离：成本利用率太差。

等 produce 大部分完成后再判 centrality：浪费最严重。

只做说话人变点或声学多样性，再假装已经知道谁是主播：信息不足。

3. 可直接放进 prompt 的 centrality rubric

下面这段可以直接使用。

### lidousha_centrality：李豆沙在该片段中的主角性（0–4）

定义：
评估李豆沙是否是该片段中事件、观点、情绪反应、冲突推进或包袱落点的叙事中心。
“发言时间较长”只能作为辅助证据，不自动等于主角；
“发言时间较短”也不自动等于配角，例如其他人可能都在围绕她的行为或反应展开。

身份判断规则：
1. 只能依据系统提供的说话人标签 `[李豆沙]`、`[其他]`、`[存疑]`。
2. “我”“我们”“我的”等第一人称代词绝不能用于推断说话人身份。
3. 不得根据措辞、语气、人物自称或上下文自行把未标注话语认作李豆沙。
4. 若核心转折、主要立场、关键反应或包袱落点对应的说话人是 `[存疑]`，
   则不得输出 0–4 分；应输出 `speaker_status = needs_human_review` 和 `level = null`。
5. 身份存疑不是内容质量较低，不能通过 uncertainty_penalty 代替人工审阅。

评分锚点：

4 — 明确主角
李豆沙明确主导片段的主要事件、观点、情绪转折或包袱落点。
至少一个决定片段成立的关键推进或高潮来自 `[李豆沙]`；
其他人的话主要是在回应、配合、追问或围绕她展开。
去掉李豆沙的关键发言或行为后，片段的核心内容基本不再成立。
通常主播发言占比为 dominant，但若占比不高，必须有明确证据说明其他人仍然围绕她展开。

3 — 明确中心参与者或共同主角
李豆沙不是唯一中心，但她有不可忽略的关键推进、明确立场、主要反应或包袱贡献。
去掉她后，片段仍可理解，但吸引力、冲突、信息量或笑点会明显下降。
另一名参与者可以同样重要，但不能明显压过李豆沙。
通常主播发言占比为 mixed 或 dominant。

2 — 有实质参与，但不是主要中心
李豆沙有相关且有内容的发言或反应，但片段的主要事件、核心信息或主要笑点
至少同等程度由其他人推动。
去掉她后，片段的基本故事仍成立，只是少了一部分补充、回应或互动。
常见于共同讨论中她只贡献一个普通观点，或主要负责承接别人。

1 — 边缘参与
李豆沙只做简短提问、附和、笑声、主持衔接或局部反应；
主要叙事、立场、事件推进和包袱落点均来自 `[其他]`。
去掉她的部分，片段的主要意义和可看性基本不变。
通常主播发言占比为 trace 或 low，且没有主播主导的关键节点。

0 — 不构成该片段的参与中心
李豆沙没有可确认的实质发言或行为；
或者只有无内容的语气词、招呼、短促笑声，而所有实质内容、推进和落点均属于 `[其他]`。
0 分必须建立在说话人归属已经确认的基础上，绝不能用于表示“说话人不确定”。

证据合同：
输出必须包含：
- `level`: 0–4 或 null
- `speaker_status`: verified / needs_human_review
- `host_speech_share_band`: trace / low / mixed / dominant / unavailable
- `evidence`: 2–4 条带时间戳和说话人标签的证据
- `counterfactual`: 一句话说明“去掉李豆沙后，这个片段还剩下什么”
- `reason`: 说明谁推动了事件、谁表达了核心立场、谁承担了主要反应或包袱

额外限制：
- 评为 3 或 4 时，必须至少引用一条 `[李豆沙]` 的关键推进、立场、反应或落点证据。
- `[其他]` 说出的第一人称叙述只能证明该其他说话人的经历或立场，不能证明李豆沙是主角。
- 若全部关键证据都来自 `[其他]`，只能评 0 或 1。
为什么它能抗住“人人说我”

因为它把两个问题严格拆开：

这句话是谁说的？
只能由外部说话人标签回答。

这个人是不是叙事中心？
才由 LLM 根据内容回答。

“我被骗了”“我当时想”“我觉得他是狼”等第一人称内容，不再携带任何身份信息。若标签是 [其他]，这些再生动也只会增强“其他人是主角”的证据，从而自然把李豆沙 centrality 拉到 0–1。

同时，评分增加了一个反事实测试：

去掉李豆沙的贡献，片段是否仍基本成立？

这比模糊的“不可替代性”括号稳定得多。

4. “单人直播除外”如何 fail-closed
先纠正判断单位

不建议以整场直播为单位做永久豁免。应优先判断候选区间是否只有主播语音。

原因很直接：

名义上的单人直播可能出现游戏 NPC、语音连麦、视频素材、TTS 或临时嘉宾。

多人直播中的某个候选区间，也可能只有李豆沙连续独白。

因此，“整场是否单人”与“该候选能否免 speaker attribution”并不等价。

最安全的实现是：轻量主播检测对所有候选都跑；高置信单人候选会自动快速通过。 “单人”成为检测结果，而不是跳过检测的输入假设。

必须采用三态，而不是二态
SOLO_VERIFIED
MULTI_VERIFIED
UNKNOWN

其中：

UNKNOWN 按多人处理，要求说话人检测。
信号权重
可以作为强证据

结构化节目 roster 或可信 ingestion metadata 明确只有主播。

候选音频的高置信语音几乎全部匹配主播。

没有持续的高置信非主播语音。

已知、稳定的直播模板明确只有一个人物声道或一个主播源。

只能作为反证或软告警

标题和分区；

弹幕中出现人名；

画面上出现头像框；

声学多样性。

标题没有嘉宾名字，不证明没有嘉宾；弹幕没提别人，不证明没人；一个头像框也可能是布局限制；声学相似也可能是不同但音色相近的人。

可执行判据

仅当以下全部成立，才输出 SOLO_VERIFIED：

A. 有可信的 solo 正向来源：
   - 结构化节目配置 / ingestion roster / 明确 allowlist；
   - 不能仅依赖标题没有嘉宾名。

B. 没有任何强多人反证：
   - 没有已知嘉宾 roster；
   - 没有可靠识别出的持续多人头像或连麦面板；
   - 没有高置信非主播连续语音。

C. 对当前候选的轻量声学审计通过：
   - classified_coverage >= 0.95
   - host / (host + other) >= 0.98
   - unknown_share <= 0.05
   - 没有长度 >= 2 秒的高置信 OTHER 连续段

其余全部为：

UNKNOWN → 按多人候选处理

标题、弹幕或画面出现明确嘉宾名字时，可以直接变为 MULTI_VERIFIED；但只出现模糊的人名、游戏角色名或观众称呼时，应降为 UNKNOWN，而不是武断判多人。

5. 如何守住“存疑转人工”而不淹没人工

核心原则是：

任何仍可能发布的存疑候选必须人工；已经能依据其他独立条件安全淘汰的候选，不必为了给它一个完整分数而送人工。

这不违反所有者规则，因为后者根本没有进入发布判断。

三级升级链
一级：轻量 PVAD / CAM++ host matcher
      ↓ 存疑
二级：更密集窗口 + 完整候选 diarization / 独立视觉信号
      ↓ 仍存疑
三级：人工审阅

二级不能只是“同一个模型再跑一次换个阈值”，而应增加新信息，例如：

更密集的语音窗；

完整候选级 diarization；

主播 cluster 映射；

重叠语音检测；

可靠的视觉 active-speaker 信息。

完整 diarization 本身也会受到 speaker profile 合并、拆分和重叠语音问题影响，因此仍需保留 abstain，而不能把它视为绝对真值。

只有 centrality 可能改变“发布/不发布”或 top-k 排名时，才进入 speaker escalation。

这会显著缩小人工面。

人工审阅对象也应缩小

不要把整条几分钟候选丢给人重新看。自动提取：

2–4 个会决定 centrality 的关键语音段；

每段前后 2–3 秒上下文；

对应 ASR；

系统给出的 [A] / [B] / [存疑]，避免先写死人物名造成锚定；

一段干净主播参考音频。

人工只需回答：

1. 关键段是不是李豆沙？
2. 哪些关键段仍无法判断？
3. 在确认归属后，centrality 是 0–4 中哪一级？
队列保护

设置的是 fail-closed 容量门，不是放宽准确率：

若 decision-relevant 人工队列超过容量：
    job_status = BLOCKED_REVIEW_CAPACITY
    禁止自动发布

不能为了压低审阅率而扩大 HOST 自动通过区间。

应监控：

speaker_abstention_rate
decision_relevant_review_rate
false_host_rate
false_other_rate
review_time_per_candidate
按节目类型 / 游戏 / 嘉宾 / BGM / 变声方式分层

若某类直播存疑率特别高，修复应是增加该类 enrollment、改模型或增加视觉/重叠检测，而不是改小 UNKNOWN 区间。

7. 对所有者要求的直接评价
所有者在认识论上是对的

没有说话人归属，就不能从多人第一人称混合文本判断李豆沙是不是主角。

这是硬约束，不是 prompt wording 能补救的软问题。当前裸 ASR 下的 centrality 根本没有测量有效性。

但“必须完整说话人分离”作为实现要求过强

完整 diarization 解决的是：

有哪些说话人，以及每个说话人在什么时候说话？

你这里真正需要的是：

这一时段是不是李豆沙？关键句是不是她？她的发言占多少？

后者是目标说话人检测，不需要知道其他人分别是 A、B、C，也不需要把所有非主播聚成稳定人物簇。Personal VAD 的任务定义正是只识别 target speaker，而不区分各个 non-target speaker。
ar5iv

而且完整 diarization：

可能只给匿名 cluster；

仍需把 cluster 映射到李豆沙；

会出现同一人拆成多个 cluster、多人合成一个 cluster；

重叠语音仍是专门难点。

+1

所以它既不是必要条件，也不是充分条件。

我建议把所有者要求重新写成可验证的功能要求：

在评估 lidousha_centrality 前，系统必须提供经校准的 [李豆沙] / [其他] / [存疑] 归属，以及候选中的主播语音占比区间；任何影响核心转折或包袱的存疑归属不得自动评分或发布。系统不要求识别每个非主播的具体身份。

这给出了与“必须完整分离”相同的安全保证，但避免了解决不需要的问题。

如果所有者坚持“分离”必须字面上等于完整 diarization，那么次优方案是：

六维候选提出
  → 安全上界剪枝
  → 候选级完整分离，作为 produce 的第一个步骤
  → centrality
  → 最终选择
  → 其余 produce

仍然不要全场提前跑，也不要等封面和烧录之后再判。

最终执行决策

采用以下设计：

1. 删除召回 prompt 中旧版裸整数 centrality。
2. 初召回只打六维，centrality=null。
3. 用 [B, B+25] 做安全剪枝和候选优先级排序。
4. 对剩余候选运行 VAD + CAM++ 目标声纹预检。
5. 输出 HOST / OTHER / UNKNOWN 和 host_speech_share_band。
6. 把标签按时间对齐到现有 ASR。
7. 使用 centrality_v2 rubric 和证据合同评分。
8. 关键说话人 UNKNOWN → 二级完整候选分离。
9. 仍 UNKNOWN 且候选可能发布 → 人工。
10. 最终胜出者才进入重转写；完整分离必须早于封面、烧录和打包。
11. known non-host 自然评 0/1；unknown 永远不是低分，而是 null。
12. v1/v2 双写、分版本统计，禁止做线性映射或跨版本直接比较。
最没把握的部分

最不确定的是“现成 CAM++ 短窗余弦匹配”在你们具体 VTuber 音频域里的 abstention 率和误归属率。 CAM++ 是高效 speaker-verification 网络，但短语音、多人重叠、游戏人声、BGM、主播夸张变声和笑声都可能使简单窗口匹配失效。它适合作为 MVP，不应未经域内 challenge set 校准就成为自动发布证据。

第二个未验证点是实际“十倍便宜”是否成立；这取决于候选总覆盖率、模型冷启动、I/O、设备和当前完整分离实现，必须用同一硬件上的 P95 端到端计算量验收。

第三个风险是：发言占比只是主角性的辅助变量，不是主角性的定义。 因此不能把 centrality 完全改成一个按语音秒数映射的确定性分数；仍需保留带说话人证据的语义判断和反事实测试。
