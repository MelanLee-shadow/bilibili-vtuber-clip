## 二、⚠️ 决定性发现：根因是**边界**，不是 metric

按 Ivan 说的"应该再往后切一点"去查弹幕，结果是可量化的：

| 区间 | 弹幕密度 |
|---|---|
| **当前切点内**（578–654s，76 秒） | 37 条 = **0.49 条/秒** |
| **切点之后 40 秒**（654–694s） | 28 条 = **0.70 条/秒** ← 全场最密 |
| 全场平均（1794 秒） | 602 条 = 0.34 条/秒 |

**观众反应的高峰整个落在切点之外。** 逐条看那 40 秒：

```
654s 问号 / 你神了 / 为什么不刀
660s ★ 只能吃一次          661s ★ 只能吃一次   ★ 一局只能吃一次、
663s ★ 只能吃一个啊姐姐      664s ★ 吃不了了
665s ★ 大姐你看看技能介绍吧你一轮只能吃一个
666s ★ 每轮只能吃一次 / 吃不了，一局吃一次 / 只能吃一次啊
671s ★ 宝宝你看你坏的        672s   李姐太搞笑了
690s ★ 黑白小猪
```

Ivan 说的"最后想吃尸体没吃到就被发现"这层反转、以及"弹幕说她坏女人"的观众高光，
**全部发生在 654.17s 之后——也就是当前切点结束之后。**

### 由此得到的判断

**`audience_salience = 2` 对"实际被切出来的那 76 秒"很可能是对的；错的是那 76 秒本身。**

这是**一个边界缺陷伪装成了评分缺陷**。如果只按"分数偏低"去调权重或降门槛，
就会掩盖真正的问题，并开始批量发布**在包袱抖响之前就结束**的片子。

**修复优先级必须重排：边界 > metric。**

## 三、三个可分别落地的缺陷

### B1（最高）：边界在包袱之前收尾
《auto_223750_578_654》的 payoff 与观众爆点在切点后 0–40 秒。
需要查 `boundary_resolver` / `boundary_semantic_review` 为什么在此处收尾，
以及**弹幕密度是否参与边界判定**（若不参与，这是一条明显可用的信号：
爆点后移 40 秒，密度 0.70 vs 0.49）。

### B2：`lidousha_centrality` 既测错、又用错
- **测错**：候选 2 / 3 分别拿到 4 和 3，而 Ivan 说这两条"主要发言人不是李豆沙"。
- **用错**：它现在是 25% 权重的可补偿维度；按 Ivan 的规则应是**闸门**
  （非主角 → 直接低分/不发，不用看别的）。与 Pro 的结论一致。

### B3：metric 改语义路径 OR（Pro 方案）
立项依据现已成立（排序反转 = 系统性拒绝）。但**必须排在 B1 之后**——
在边界修好之前，用被截断的窗口去标定新 metric 会把错误固化进阈值。

另：现有七维**没有一维对应 Ivan 说的"一波三折 / 弱→强→弱"叙事弧**。
`persona_reversal`（10%）量的是人设反差，不是剧情起伏。这可能是缺一根轴。
