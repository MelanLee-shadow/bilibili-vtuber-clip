# 切片流水线：操作说明

第一次搭建见 [从零搭起来](../../profiles/SETUP.md)。这里写日常怎么跑、每一步谁来判、停下时去哪里看原因。

判断由模型做（经模型网关，凭据在媒体主机的 `cpa.env`），结果直接采用；流水线只在工具失败或输入缺失时停。
唯一不放行的是字幕里「定不下、而且影响意思」的句子（规则原文在 `doubt_policy.HOLD_RULE`）：
这样的片照常做到成片包，只是不封存。

## 步骤与顺序

执行顺序是 1（边界）、0（外片查重）、2–9。`run --until N` 跑到第 N 步。第 10 步（上传）不在公开版里。

| 步骤 | 内容 | 谁判 |
|---|---|---|
| 1 边界 | 模型判起止，采用它的切点（两项常识检查：在源录像内、时长 30 秒到 10 分钟） | 模型 |
| 0 外片查重 | 平台上已有内容完全相同的切片才拦 | 工具 |
| 2 剪辑 | 媒体主机 ffmpeg，校验时长 | 工具 |
| 3 字幕 | 两份免费识别稿打底；片里听得到主播以外的声音时（按主播声纹判断，`voices.py`），整片再送 MAI、MOSS 各识别一次，也给第 4 步提供说话人分簇；只有主播一个人的片不送。疑点来自：识别稿之间不一致、模型整片审读、名表、漏句、相接处重复、念弹幕。疑点逐级加证据，定下即停：先只对疑点窗口重识别，再让音频模型复听（模型和顺序在 `assets/manual_lane/lane_rules.json` 的 `listening`）；仍定不下时模型选最可能的写法并标成低把握。三个代理各自独立写一遍，逐处取多数。导入的人工字幕（`import-subtitles`）就是本步的已定字幕 | 模型 |
| 4 说话人 | 只有主播一个人的片：全部标主播。两位以上参与者：整片识别的每个说话人簇和主播登记的声纹比对，最像的一簇是主播、其余是嘉宾；几路声音证据不一致的句子交模型按语境复核，只有本句里明确的内容证据（自称、自报身份、只能出自一方的话）才改声学给出的标签。画面里在放别的视频时，读那条视频自带的字幕来区分主播和视频里的人。声纹工作区没配时，这类片停在本步并写明缺它 | 工具＋模型 |
| 5 烧录 | 字幕烧录；profile 启用片头时前置片头，缺文件即停；片头清单写 `enabled: false` 的频道不加片头。和第 6 步互不依赖，同时进行 | 工具 |
| 6 标题与封面 | 只读最终字幕。标题：模型按频道的编辑方法（`assets/<id>/title_editorial_method.json`、`title_style.md`）出候选，过发布硬门（`title_policy.json` 的禁用词等），再由验收模型按字幕核事实。封面从便宜的做起：先评截图，有合格的就用；都不合格才生图 | 模型 |
| 7 标签 | 模型按最终字幕出，直接采用 | 模型 |
| 8 成片包 | 组装视频、字幕、封面、标题、简介、标签，做成片检查 | 工具 |
| 9 复审 | 另一个模型读一遍成稿，修改直接采用（改了字幕或说话人就只重建烧录、标签和成片包）。仍有「定不下且影响意思」的句子就不封存，其余封存 | 模型 |

## 状态、记录与续跑

- 每条片一个状态文件 `<任务目录>/state/<片号>.json`（各步状态、产物路径、模型调用、短说明），和
  `<任务目录>/clips/<片号>/PROCESS.md`（每一步做了什么、模型怎么判、采用了什么）。**某一步停下时，原因写在这两处。**
- 续跑只看产物：某一步记为完成且产物都在，就跳过。要重做某一步及其后续，用 `redo --from <步骤>`，不要手删文件。
- 停下就读原因再处理，不要重复运行去碰运气：缺输入就补输入，工具失败就修工具。

## 命令

入口都是 `python3 scripts/manual_lane.py <命令>`，频道用环境变量 `AUTOSLICE_PROFILE=<id>` 选。每个命令的全部参数见 `--help`。

- `preflight`：开工前自检——频道文件和媒体主机上，各步要读的东西一次查完（不改任何东西、不调用模型）。
- `discover --task-dir T [--date YYYY-MM-DD]`：一天的录像 → 整场识别稿 → 候选片 → 排座入选 → 为每条入选的片建状态文件。
  不给日期时取录像根下最新的、已经录完的日子。可重复运行，做过的不重做；账本在 `T/discover/ledger.json`。
  这个房间还没有录像目录时会明说（`NO_RECORDINGS_YET`）；录像根目录本身不存在是配置错，报 `ARCHIVE_ROOT_MISSING`。
- `status --task-dir T [--cid C]`：一条片的步骤表；不给片号时是这个任务的发现账本和各条片的片号、做到哪一步。
- `run --task-dir T --cid C [--until N]`：跑一条片；`--cid` 可重复，几条片并排跑，各有自己的日志。
- `auto --task-dir T`：无人值守的一轮——发现新的录像日，把没做完的片接着做；同一处连停三轮的片留给人看。
- `redo --task-dir T --cid C --from <步骤名或编号>`：忘掉这一步和依赖它的步骤，下次 `run` 重做。
- `import-subtitles --task-dir T --cid C --source-dir D --source 名字 --authority <依据>`：人工定好的字幕和说话人成为第 3 步的输入，从第 3 步起重跑。
- `import-cover`：人工做好的封面原样成为第 6 步的封面。
- `compile`：同一场直播里同一主题的几段合成一条（规则见 [20-selection](20-selection.md)）。
- `trim`：把成片里无关的致谢段剪掉，生成一条新片。
- `listen-queue` / `listen-import`：把「定不下且影响意思」的句子做成听音页给人听，再把人的标注导回。
- `score --task-dir T --truth J`：按人工定稿打分（只评估，不改任何产物）。
- 加 `--on-media-host`：控制端就在媒体主机上运行时用；默认经 ssh。

`revise`、`record-title-receipt` 和 `run --upload` 处理已发布的视频，依赖频道自己的出版登记和上传工具，公开版里没有这部分。

## 配置在哪

- 主机、部署目录、工作根、录像根、字体、检索地址：`profiles/<id>/manual_lane.json`（`layout.py` 读；每项可用环境变量
  `MANUAL_LANE_<键名大写>` 覆盖）。代码里不写主机路径。
- 用哪个模型、几遍、阈值、并发：`assets/manual_lane/lane_rules.json`。
- 关于这个频道、会进提示词的几句话：`profiles/<id>/manual_lane_channel.json`；提示词模板在 `assets/manual_lane/prompts/`，
  里面只有占位符，没有任何一个频道的内容（`tests/manual_lane/test_channel_neutral.py` 守着这一条）。
