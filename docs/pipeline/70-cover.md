# 70 封面

封面默认采用**真实截图优先、AI 次选**。先从绑定源帧中选择清楚、好看且能说明
事件的画面；只有源帧无法满足身份、构图或画质要求时，才进入截图轻修或受审的
图像生成路线。截图直出记录 `image_generation_used=false`，不能伪造生图回执。

游戏场景应保留完整、可辨识的游戏画面；若有固定主播小窗，必须同时验证小窗
身份和画面事件。谈话场景应保留真实人物、服装和可见物件，不能用 AI 补入未见的
参与者或故事事实。未知内容保持 UNKNOWN，不用运动几何或模板猜测替代画面证据。

Talk 封面使用短梗字和能说明事件的图像。文字可以是标题的补充、缩写或改写，
但必须来自当前 StoryContract/审查结果；不能把完整长标题自动塞进封面。标题、
封面和画面共同通过事实归属检查。

标题—封面联合检查须使用当前包已绑定的源图—成品身份见证，重验同候选、同成品及
包内参考图/对比图/原始模型回执的哈希和完整裁决，再将其传给检查模型。旧 PASS 不得
自动填写新结论；当前文字、构图、图文一致性和可见身份冲突仍需新的模型裁决。

排版由受信字体和确定性 renderer 计算实际 glyph/bbox。Talk 文字保持 1–2 行，
字号低于 120px 或 glyph 被裁切时阻断并换文案/版式；最终 PNG 必须重放文字层、
尺寸、字体和像素哈希。截图路线不产生 AI model 证据，实际轻修或重绘必须记录
真实模型和输入输出哈希。

封面通过只表示当前封面候选有效，不表示视频已打包或已发布。

文字与画面 CPA 审查累计记录实际调用，以软目标表达资源压力，不因累计次数达到
目标而跳过必要裁决。相同画面与证据优先复用已验证结果；没有新证据、没有进展或
出现循环时保留未解决项并停止重复请求。封面几何与 provenance 必须记录实际采用的
fit 方式、源图和输出像素，不能用另一种排版方式的回执为当前成品背书。
