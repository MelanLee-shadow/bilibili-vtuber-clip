# 独立输入的批处理边界

普通入口对多个独立输入逐项读取时，单个输入消失、不可读、无法解码或内容不合法，
只影响能独立保留或重试的最小条目。使用 `src.autoslice.batch_items.ItemBatch`
记录条目、原因码、异常类型与详情；成功结果在输入检查成功后才能写入或进入计划。
原因码为 `ITEM_DISAPPEARED`、`ITEM_UNREADABLE`、`ITEM_INVALID`。

边界只包输入操作。配置、策略、发布登记、锁、输入/回执身份绑定、检查点和结果持久化
属于整轮权威，错误向外传播；`ItemAuthorityError` 即使位于条目边界内也不能被隔离。
调用者必须显式选择能确认是输入错误的异常类型，不把未知程序异常或 provider 授权错误
一概当作坏条目。

- GC 扫描以运行分组为单位；无法完整读取的分组保留并记录，其他分组继续。
  计划阶段重新读取目标身份；读取失败则撤回该组所有目标与计数。消失文件不进删除集合。
  保留期、活动保护、发布保护和 apply 的批准集合及身份复核不变。
- 普查先验证清单结构，再逐文件读取、解码和逐窗口标注。缺失源、解码失败和坏标注
  记入 `batch-result.json`，成功阶段仍可复用。部分结果位于独立 `partial/` 快照并标为
  `PARTIAL`，报告分母仅为成功窗口；重新执行重试失败项，完整结果仍写原 run 根。
  输入 SHA、窗口身份、缓存与 create-only 冲突继续整轮拒绝；网络/授权错误不隐式降级。
- 既有说话人审阅 CLI 已逐候选记录 failure；生产调度已逐候选生成失败结果，事务/回执
  错误继续向外传播。包导入、发布批事务、OSS 导出的一致性检查不是独立输入集合，
  不能跳过其中一个文件来制造完整包或有效事务。
- 只读媒体引用扫描器逐交付记录、日状态隔离坏输入，将原因码写入 stderr 的
  `BATCH_ITEM_ISOLATED` JSON；原有引用结果 JSON 数组保持兼容。

回归入口为 `tests/test_batch_item_isolation.py`，同时走普通 GC CLI、普查 CLI 和一个
未用于设计修复的说话人批处理。更改或新增独立批入口时，将普通入口加入此行为对照，
不要只测试手工构造的 helper 中间值。全局 typed ratchet 要求共享模块进入完整 strict 检查。
