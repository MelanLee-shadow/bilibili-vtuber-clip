# 频道词表（glossary）——专名与误听黑名单

写法（解析器契约）：每行一个 `- ` 条目；条目里「不要写成 X / 不要改成 X /
听成 X 等」子句会被解析成误听黑名单，喂给字幕术语 QA 门。

## agent 首次配置时，向频道主人问这些

- 主播名/自称/常用昵称？粉丝团怎么称呼？房间号/直播间自称数字有没有？
- 有哪些固定梗词、口癖、圈内黑话？哪些是"这是梗、只有一种写法、无例外"的硬替换（hard-meme-canon）？
- 哪些专名 ASR 经常听错？错成什么样？误听候选需要哪些额外证据（结构化弹幕/SC、接话链、时间区间）才能定？
- 常联动的主播/团体叫什么？完整名单锚定在哪张表？
- 主播说方言吗？方言词的"正确"修复方向是保留方言还是转普通话？
- 主播有没有夹外语（如日语）插话的习惯？怎么处理？
- 有没有 CP/关系类简称、数字站位（1/0）这类需要逐字保留、不能被"纠正"的说法？
- 主播有没有真实口吃/重复口癖？转写时怎么保留又不糊连？

## 校正机制铁律（框架；具体术语表由运营持续积累）

- **hard-meme-canon 铁律**：如果某误听词已被认定为频道内部固定梗写法（不存在需要保留的"真"义项），字幕/标题/封面一律无例外替换为梗写法；流水线做确定性替换，LLM 修正时同样遵守。
- **词形等价类压缩铁律**：一个专名如果存在多个同音/近音/大小写变体写法，一律压缩为唯一 canonical 写法；不保留误听变体，也不因误听变体"看起来更常见"而反向覆盖 canonical 写法。
- **误听候选证据门槛**：某专名的已知误听面只用来提高候选优先级，不能单凭"词已在词表中"就盲选；最终改写需要本句读音证据、结构化弹幕/SC、同一接话链、重复专名槽或已审定的源时间区间等实证支持。
- **主语误听连锁效应**：当某专名作句子主语时，ASR 可能把"专名+助词"这类结构整体误听成完全不相关的怪短语；这类怪句应先按目标专名读音与近窗证据复核，证据成立才还原，不能想当然展开成"正常句子"。
- **反向保护铁律（自称保护）**：主播的常见误听修复方向不能被无差别应用——她自称自己时，绝不能被上下文里出现的其他人名带偏、误改成别人的名字。
- **局部序列 authority**：当原句是连续枚举同音候选人名/词的模式时，逐个按枚举顺序落字，不做全局互换；这是局部证据，不能推广成全局替换规则。
- **固定序列梗保护**：如果某组词是主播固定连说的名词序列梗，序列内的单字近音 token 应按序列成员词修复；如果是来自结构化 SC/弹幕的问候串，以原文为准，不能被拆出或丢字。
- **方言词保护铁律**：方言词是主播口播的真实内容，修复方向必须保留方言写法，禁止"纠正"成普通话同义词——这与通用中文纠错的默认方向（归一到规范普通话）正好相反。修复裁决优先序：方言原字 > 普通话意译 > 保留误听。
- **结巴/重复词渲染规范**：真实口吃的重复要忠实保留，但必须带停顿标点分隔，禁止糊连成一个词；这是转写风格约束，不是改写。
- **日语插话规则**：判定是日语插话就按日语原词或对应中文义写，不要硬转中文谐音；她真说中文时也不要反向改写成日语。
- **外来词/音译词归一规则**：某外来词有多种非正式读音时，字幕统一写成其惯用缩写/官方写法；先核对相关结构化数据（如SC/弹幕原文）以确定实际内容再落字。
- **名单锚定校正原则（联动/同团主播等）**：提到常联动主播时，人名先对照锚定名单（含别名）再落字；名单外的音近人名不要造词。

## 真实示例（格式demo，来自李豆沙频道，示范写法与机制）

（示例）梗词：掏兜（薅弹幕/抢钱/偷学技能那套玩笑里的说法）。不要写成偷渡、淘兜、掏斗。
（示例）品牌/话题词：和成天下（槟榔品牌；相关方言语境里也称"大果"）。ASR 常误写成"合成天下/何成天下"，一律写成和成天下；不要与另一个名称"和天下"混为一谈。
（示例，李豆沙，示范"等价类压缩+证据门槛"机制）人名/ID：kmx（她常提到的人，会喊 kmx 妈妈/宝宝；实际口播发音是"kimo熊"，不是逐字母 k-m-x）。一切 kimo熊 系写法一律压缩写作 kmx；已知误听候选只能提高候选优先级，最终仍须本句读音、结构化弹幕/SC、同一接话链或已审定源时间区间支持，不得因词已在词表中就盲选。
（示例，李豆沙，示范"方言词保护"机制）长沙话方言词：恰（长沙话＝吃，最高频方言词，如恰饭、恰烟恰酒）。ASR 常把"恰X恰Y"误听成"查X查Y/掐X掐Y"；烟酒/吃喝语境下的对应音优先判为"恰"，写方言原字，不要"纠正"成普通话"抽烟喝酒"。

## 积累纪律

从 3–5 条起步就够开跑；之后每次误听裁定、每个新梗随手加一条。这个文件是运营沉淀出来的，不是一次写完的。
