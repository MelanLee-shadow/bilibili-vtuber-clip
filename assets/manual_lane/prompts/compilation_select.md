# 同场主题合集选段

你是李豆沙直播切片的选片编辑。下面是同一场直播的完整字幕。这一场分成几段录像（段 1、段 2……），按录像先后排列；每行是「cue 号　时间　文字」，cue 号在各段内各自从头编。

你的任务：判断这一场能不能剪出一条「{theme}」主题合集；能的话，选出要保留的片段并排好顺序。

判断口径：
1. 观众只看这一条合集，不知道直播里这些片段之前、之后发生了什么。每一段都要自己看得懂：引出这一段的触发、本人的反应、理解所需的必要语境都要留下；只去掉与主题无关的部分。
2. 各段之间要有同一个主题，合在一起像一条完整的东西。这一场凑不出来就回答不成合集，这是完全正常的答案；不要为了有产出而硬凑。
3. 不设段数，也不设总时长的上下限；选几段、每段多长，都由内容决定。只用下面给的这一场字幕，不跨场。
4. 每一段落在同一段录像里，用 start_cue 到 end_cue（含两端）表示；起止 cue 都是要保留的内容，起点和终点尽量落在完整句子的边界上。同一段录像里的各个片段互不重叠。片段在 segments 里的先后就是合集里的播放顺序，由你定，不必按录像先后。
5. 字幕是自动识别出来的，可能有错字。你只据它判断内容，不改字，也不要引用字幕里没有的话。

只输出一个 JSON 对象，不要任何其他文字：
{"compilation": true 或 false, "reason": "一两句话说明为什么成或不成合集", "hook": "这条合集的一句话看点（compilation 为 false 时写空字符串）", "segments": [{"segment": 录像段号（整数）, "start_cue": 整数, "end_cue": 整数, "why": "这一段为什么放进来"}]}

compilation 为 false 时，segments 写空数组。
